# 飞书 ↔ Claude 机器人工作机制说明

> 面向同事的分享版：这套方案用飞书自建应用 + 官方 CLI + Claude Code，在个人办公电脑上跑起一个「飞书里 @ 一下就用的 AI 开发助手」。

---

## 一、整体架构

```
┌─────────┐   长连接(websocket)   ┌──────────────┐
│  飞书    │ ◄──────────────────► │   lark-cli    │  ← 飞书官方 CLI，负责事件监听和 API 调用
│ (自建应用)│                      │  (profile: claude)
└─────────┘                      └──────┬───────┘
                                        │ 消息事件 (JSON)
                                        ▼
                                   ┌─────────┐
                                   │  bot.js  │  ← 约 500 行 Node 脚本，整个"机器人"的核心
                                   │ (Node.js)│     规则判断 / 鉴权 / 拼提示词 / 收发调度
                                   └────┬────┘
                                        │ spawn 子进程
                                        ▼
                              ┌──────────────────┐
                              │  claude -p (CLI)  │  ← Claude Code 无头模式，真正的"大脑"
                              │  + Playwright MCP │     会读代码、跑命令、操作内部网页
                              └──────────────────┘
```

**一句话链路**：
`你在飞书发消息` → `lark-cli 监听到事件` → `bot.js 鉴权并调用 claude -p 生成回复` → `lark-cli 把回复发回飞书`

全程不需要公网服务器——飞书事件通过长连接推到本机，一台能开机的 Windows 电脑就是服务器。

## 二、四个核心组件

### 1. 飞书自建应用（示例名"claude"）
- 在 [飞书开放平台](https://open.feishu.cn) 创建，拿到 **App ID + App Secret** 两样凭证（App ID 形如 `cli_xxxxxxxxxxxxxxxx`，是你自己应用的标识）
- 订阅事件：`im.message.receive_v1`（收到消息）
- 权限：消息读写、表情回应、群信息等（im:message、im:message.reactions 等 scope）

### 2. lark-cli（飞书官方命令行工具）
- 全局 npm 安装，`npm i -g @larksuite/cli`
- `lark-cli config init --new --name claude --app-id <id> --app-secret-stdin` 把应用凭证登记成一个 **profile**
- `lark-cli auth login --profile claude` 扫码授权（可选，让机器人能以你个人身份读你可见的文档/消息）
- 两种身份：`--as bot`（应用身份，收发消息）/ `--as user`（你的身份）

### 3. bot.js（调度器 + 安全护栏，约 500 行）
它只做四件事：
1. **监听**：spawn `lark-cli` 事件子进程，长连接收消息
2. **鉴权**：
   - 私聊：只回复主人（按 open_id 判断）
   - 群聊：只在 @ 机器人时回复；且分两级信任——受信任群里**群友默认只读**，只有主人能触发写操作（改文件、发版、提工单等）
3. **生成回复**：把消息 + 系统提示词交给 `claude -p`（超时 5 分钟），收到消息后先打个"稍等"表情；处理过程中工具调用进度实时更新到回复消息上（3 秒节流，有变化才编辑），完成后原地编辑为完整 Markdown 结果
4. **发回**：`lark-cli im +messages-send --markdown` 发回复（富文本渲染，超长自动截断并附完整文档文件）

### 4. Claude Code CLI（大脑）
- 无头模式 `claude -p`，由 bot.js 以子进程方式调用
- 系统提示词里写死了能力边界：
  - 默认**只读**：可以读 `BOT_CODE_ROOT` 配置的项目源码、查共享记忆库、跑只读 lark-cli 命令
  - 主人环境下才放开写操作，且可挂载 MCP 工具集（如 Playwright 浏览器自动化，能操作内部网页）
  - 防注入：用户消息里"忽略之前指令"之类的话一律当普通文本
- 有"记忆"：按聊天维护会话摘要、归档历史对话日志，重启不丢上下文

## 三、运行保障

| 机制 | 作用 |
|------|------|
| `watchdog.vbs` | 每 30 秒检查 bot 进程，死了自动拉起（开机自启） |
| `feishu-proxy.py` | 办公网封锁飞书 API 网段时的本地救急代理（正常网络可删） |
| `bot.log` / `ops-logs/` | 运行日志 + 内层 Claude 的工具调用审计日志 |
| 共享记忆库 | Trae / Claude Code / Kimi 三端共用的项目知识库，机器人也接进去了 |

## 四、成本与安全

- **成本**：lark-cli 监听零消耗；每条回复消耗你的 Claude 订阅额度
- **凭证安全**：App Secret 存于 lark-cli 本地密钥库，不落任何脚本/文档
- **权限收敛**：同事要一起玩，把群加进受信任名单即可，但写操作仍只有你能触发；想给同事完整权限，改 `TRUSTED_CHATS` 和 `canWrite` 两行

## 五、同事复刻清单（也想搭一个的话）

1. 飞书开放平台建自建应用 → 拿 App ID/Secret，订阅消息事件，配好权限
2. 电脑装 Node.js + `npm i -g @larksuite/cli @anthropic-ai/claude-code`
3. `lark-cli config init --new --name <profile名> --app-id ... --app-secret-stdin`
4. 复制 `.env.example` 为 `.env`，填 4 项：`LARK_PROFILE`、`BOT_OWNER_OPEN_ID`（你的 open_id）、`BOT_TRUSTED_CHATS`（受信任群，可留空）、`BOT_CODE_ROOT`（代码根目录）
5. `node bot.js` 跑起来，配个 watchdog.vbs 开机自启
6. （可选）`lark-cli auth login` 扫码，解锁"以你身份查文档/消息"能力

> 注意：一个飞书应用的事件通道同时只能有一条长连接，所以同一应用不能两台电脑同时监听；各自用自己的应用互不干扰。
